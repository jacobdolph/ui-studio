# UI Studio

A free web app for building **WoW Forever** Edit Mode layouts in the browser and exporting them as strings players paste into *Edit Mode → Import Layout*.

| Folder | What |
| --- | --- |
| `web/` | Vite + React + TypeScript single-page app, deployed to GitHub Pages |
| `addon/` | Companion Lua addon (placeholder for now) |

## Status

- **Codec** (`web/src/editmode/layoutString.ts`): decodes and re-encodes Blizzard's Edit Mode layout string format losslessly. Verified against 570 real exports from wago.io (every version 0–5, including WoW Forever beta builds). The format write-up is in [`web/FORMAT.md`](web/FORMAT.md).
- **Schema** (`web/src/editmode/schema.generated.ts`): every system, setting, slider range, dropdown label and preset anchor, generated by running Blizzard's own Lua from the `forever` branch.
- **Visual editor** (`web/src/editor/`): a canvas that draws the HUD the way the game lays it out and lets you drag frames, edit settings, and export a version 5 string.

### How the editor works

- `web/src/editmode/frames.ts` maps each system to its Blizzard global frame name and an approximate footprint (sizes from FrameXML, scaled by the system's own size setting).
- `web/src/editor/geometry.ts` resolves anchors into screen rects, including anchors to other frames (`relativeTo`), the WoW Forever bottom action bar stack (`UpdateBottomActionBarPositions`, relative-to-base mode), the right action bar column, and the bottom/right managed frame containers. Frames you have not moved stay in default position, so the game keeps placing them itself after import.
- Dropping a frame stores what the game stores after `StopMovingOrSizing`: an anchor to UIParent at the screen-third the frame's center is in, offsets to one decimal.
- The canvas is a UIParent of `768 / uiScale` units tall (1920×1080 units at 1080p with the default scale), so offsets match what the game shows.

The footprint of a frame is an approximation; the exported string is exact.

### Importing retail strings

Live retail (12.x) and WoW Forever share every system id up to 25 and every per-system setting id (diffed from both clients' `EditModeManagerConstantsDocumentation.lua`). Forever inserts the end caps (26) and Group Finder (27) ahead of Loss of Control, which moves from id 26 to 28. `web/src/editmode/compat.ts` rewrites that one id when a version-2 string is imported, so a retail layout means the same thing in Forever. Frames only Forever has (end caps, totem bar, swing timers) are filled in from the preset by the game's own layout reconciliation on import.

Explicit anchors only make sense on the UIParent they were made on, so importing also picks the smallest screen preset whose UI units hold every placed frame (`inferScreenId`). A layout made at 2560×1440 with the default 0.64 UI scale, for example, needs a 2133×1200 canvas.

`?layout=<export string>` opens the editor with that layout (the Export dialog's "Copy share link").

## Develop

```sh
cd web
npm install
npm run dev        # editor on http://localhost:5173
npm test           # vitest: codec, schema, geometry/editor tests + corpus round-trip
npm run eval       # per-version round-trip report over the wago corpus
```

Regenerate the enum/setting schema from Blizzard's FrameXML (branch `forever` of Gethe/wow-ui-source, strings from Ketho/BlizzardInterfaceResources):

```sh
npm run gen:schema -- /path/to/wow-ui-source --flavor camelot --strings /path/to/enUS.lua
```

## Deploy (GitHub Pages)

Every push to `main` runs `.github/workflows/deploy.yml`: lint, tests, `vite build` with `BASE_PATH=/ui-studio/`, then publish `web/dist` to GitHub Pages at https://jacobdolph.github.io/ui-studio/. The Vite `base` comes from `BASE_PATH`, so a local build and dev server still serve from `/`.
